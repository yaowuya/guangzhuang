## 评审结论

**有条件通过，已获用户确认并进入计划／执行。** D-001～D-037 均有终态记录和写入授权；本轮补齐收藏排序、首次登录、错过定时与中断恢复、入口核验、收藏标记和分页边界。前端视觉与既有架构不变。此结论表示设计具备评审条件，不表示功能已实现，也不代替写入后的阶段确认。

最重要的交付条件是：至少一个目标来源须核实访问及使用条件，并在正式运行环境完成真实标题更新。来源、图片或外链可访问，不等于已获许可。

## 业务和技术主线

单人登录后，用户浏览标题、组合筛选、查看出处、打开原文并收藏。系统每天北京时间 07:30 或按用户操作触发更新；单个后台进程读取**已核验且已启用**的固定入口，只提取标题及必要元信息。相同原文链接更新同一条目；不同链接不因标题相似而合并。

一轮更新可能成功、部分成功、失败或无新增。已成功结果及时保留，失败入口可单独重试；中断后当天自动补跑最多一次，不追补多日。图片由浏览器直接从获准来源加载，失败不影响文字与收藏。

最简单的已确认方案是 Caddy、Vue、FastAPI、一个后台进程和同机 SQLite。后台进程的必要性是长时间读取来源时仍能响应网页，并跨重启保存任务结果；不引入当前不需要的 Redis、多机集群或模型服务。设计评审时没有正式业务代码可复用，旧原型只复用视觉参考；当前实现状态须另从源码、任务 owner 和执行 ledger 核对。详见[架构主线](<design/backend.md#架构主线>)与[前端架构主线](<design/frontend.md#架构主线>)。

## 状态、并发和执行流程

任务通过数据库短事务认领；活动任务唯一约束防止重复入队。逐入口成功结果先提交，全部成功、部分成功和全部失败分别反馈；无新增不是空库。重试只处理上次失败或中断入口。

后台重启先把旧运行任务结算为中断终态、填写结束时间，保留已完成入口结果并释放活动占用；不把正常排队的任务一律作废。当天 07:30 后完全没有定时记录时，当前已核验且启用的入口构成一次补跑集合；已有记录则只补失败或未完成项。先结算再受唯一约束创建补跑，避免任务一直卡在运行中。自动补跑用尽后仍失败，等待手动重试或次日任务，不追补多日。依据：[状态流程](<design/backend.md#状态并发与执行流程>)。

PR TIMES 全站 RSS 是滚动的多行业流；规则不能确认分类的标题按已确认规则保留在“全部／未分类”，因此可能出现非美妆标题，不能承诺完整或纯美妆覆盖。

页码分页在数据不变时顺序确定；更新期间插入条目或更正报道日期可能使跨页内容位移，这是已确认的简化，不代表快照级不重不漏。首页与收藏分别使用报道日期和收藏时间排序，不能共用错误的默认排序。依据：[接口与分页边界](<design/backend.md#接口权限与兼容边界>)。

## 前端方案

使用 Vue 3、TypeScript 和 Vite。页面包括单人登录、标题工作台、收藏视图、出处侧栏和只读来源状态面板。查询条件保存在地址栏，关闭详情恢复位置；页面局部状态和少量共享逻辑足够，不引入大型组件库或全局状态框架。

视觉以[旧原型](<prototype.html>)及其桌面、手机截图为依据：浅色工作台、分类导航、标题卡、详情侧栏。登录与来源面板没有现成画面，需在真实实现后复核。完整组件层级、布局及键盘／手机检查见[前端映射](<design/frontend.md#ui-组件树与-figma-解析映射>)与[Visual Checks](<design/frontend.md#visual-checks>)。

## 主要风险、迁移、发布和验证

### 主要风险

| 具体失败场景 | 影响 | 预防或处理 | 设计依据 |
| --- | --- | --- | --- |

单机 SQLite、串行后台和本机备份是本期简化；当实测更新窗口、锁冲突或多机写入需求触发边界时，评估数据库／队列扩展。本机备份不覆盖整机丢失。无大型前端组件库和全局状态框架，若实际重复与维护成本增加再评估；当前验收和安全规则不因此降低。各项升级条件由[后端风险](<design/backend.md#风险迁移发布回滚与监控>)和[前端风险](<design/frontend.md#风险迁移发布回滚与监控>)持有。

### 迁移与发布

初版建立新表，不迁移旧原型数据。发布前核对域名、DNS、证书及服务器端口；确认备份可恢复，并验证至少一个获准来源在云环境真实更新。发布后监控每入口最后成功时间、任务失败、数据库锁及备份状态。恢复旧备份会丢失备份后的写入，需先确认损失范围；前后端及 Caddy 版本共同回退。

### 验证清单

- [ ] 逐入口核验访问、使用条件及依据，覆盖同站两个入口状态不同；网站汇总不放行待核验入口；至少一个真实来源更新成功。[依据](<design/backend.md#验证方案>)
- [ ] 用包含正文、脚本和恶意链接的受控 RSS／列表夹具验证只提取允许元信息，不保存正文、不执行脚本。[依据](<design/backend.md#验证方案>)
- [ ] 验证相同链接、定位标记、不同查询参数和不同媒体链接；不重复条目、不误做跨媒体归并。[依据](<design/backend.md#验证方案>)
- [ ] 模拟并发触发、部分失败、无新增、当天完全无定时记录与中断恢复；旧任务先进入终态并释放占用，当天自动补跑最多一次，成功结果与收藏保留。[依据](<design/backend.md#验证方案>)
- [ ] 无已有会话完成首次登录，验证错误 Origin、非 JSON、限流、24 小时到期和退出；其余写请求缺会话或 CSRF 均拒绝，日志不泄露凭据。[依据](<design/backend.md#验证方案>)
- [ ] 对照收藏时间与报道日期排序；核对首页、详情、收藏列表及写操作的 `bookmarked` 状态一致，并验证数据变化时不伪称快照分页。[依据](<design/backend.md#验证方案>)
- [ ] 验证桌面、平板、手机和键盘流程；检查标题卡、详情、收藏、来源状态及外链图片失败。[依据](<design/frontend.md#visual-checks>)
- [ ] 演练 SQLite 一致性备份和恢复，验证 Caddy HTTPS、真实来源及一次正式更新。[依据](<design/backend.md#验证方案>)
- [ ] 自审新增公共职责说明、来源与并发边界注释；与实际行为保持一致，评估已确认的单机简化边界。[依据](<design/backend.md#验证方案>)、[前端验证](<design/frontend.md#验证方案>)

## 评审顺序与抽查路径

1. **先看可用来源和授权**：核验五站启用条件、全站 RSS 的覆盖限制与至少一个真实可用来源的交付门槛。[后端风险](<design/backend.md#风险迁移发布回滚与监控>)
2. **再看数据与恢复**：七表、链接唯一性、入口结果、当天补跑和备份恢复是否满足单人使用。[数据模型](<design/backend.md#数据模型>)、[任务流程](<design/backend.md#状态并发与执行流程>)
3. **最后看接口与页面**：会话和 CSRF、标题版字段、外链降级、筛选位置和视觉基准。[后端接口](<design/backend.md#接口权限与兼容边界>)、[前端方案](<design/frontend.md#前端设计仅-ui-范围>)

建议抽查：[入口级核验字段与任务模型](<design/backend.md#完整字段定义>)、[任务恢复与首次登录](<design/backend.md#状态并发与执行流程>)、[前端视图与组件](<design/frontend.md#L80-L111>)和[前端验证](<design/frontend.md#L134-L165>)。

## 评审结论记录

- [ ] 通过：设计完整，可以进入计划阶段。
- [x] 有条件通过：用户已确认设计并进入计划／执行；正式交付前仍须至少一个来源的访问与使用条件通过核验，并在目标云环境真实更新，其它来源保持未启用直至核验通过。
- [ ] 退回修改：若来源、数据模型、任务恢复、接口安全或标题版页面不符合预期，返回对应[后端设计](<design/backend.md>)或[前端设计](<design/frontend.md>)章节定点修订。
