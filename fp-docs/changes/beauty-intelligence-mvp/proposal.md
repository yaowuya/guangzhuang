# 全球美妆研发情报台标题版个人 MVP 变更提案

## Why

本项目帮助个人化妆品研发和产品开发从业者每天集中发现资讯标题，减少跨站查找与回看成本。本站作为阅读入口，完整内容回到来源网站阅读。

[当前 PRD](<prd.md>) 已按用户在设计访谈中的明确决定收缩：不配置外部模型、不采集正文、不生成中文摘要，只保留标题和必要元信息；仅对相同原文链接去重，不再跨媒体归并事件。

这次仍以真实可用的个人 MVP 为目标，不退回纯演示。旧交互稿继续作为视觉参考，但其摘要、事件和技术信息演示不能当作标题版的目标需求或已实现能力。

## What Changes

### 1. 建设个人标题阅读应用

提供桌面优先、兼顾手机的标题列表、组合筛选、出处详情、原文跳转和收藏。界面保持中文，标题保留来源语言，不附加摘要、翻译或模型结论。

保留七类入口：新品发布、趋势洞察、新原料、研发技术、包装与剂型、OEM／ODM 和法规与合规。正式应用使用单人登录，不开放注册，不导入原型中的虚构资讯或历史图片样例作为真实采集结果。

### 2. 从固定来源取得标题与元信息

只接入经可用性和使用条件核验的固定来源，不提供任意来源管理界面。采集标题、来源、原文链接、能取得的报道日期，以及允许使用的图片外链和归属信息，不获取或保存正文。

每日北京时间 07:30 更新一次，支持手动刷新和重试。更新时保持已有列表可读；部分失败、全部失败、无新增和首次为空分别反馈，失败不覆盖最后成功内容或收藏。

候选网站清单不等于已接入或已授权。无法取得有效标题与原文链接时不创建不可使用的条目，也不绕过登录、付费或访问限制补全数据。

### 3. 按原文链接去重并采用明确分类规则

每条资讯代表一条原文链接。同链接再次收录时更新原条目的可得元信息，不生成重复条目；不同链接即使报道同一事件也分别保留。移除跨媒体事件匹配、归并及多来源事件详情。

分类、地区和品类仅依据来源栏目与标题明确词语。无法确定时标未分类或未披露；未分类仍能从“全部”阅读，不把网站所在国家直接当作产品上市市场。

### 4. 提供组合查找与出处详情

关键词搜索限定在标题和必要元信息，结合分类、地区、品类及报道日期缩小结果。不提供正文或摘要搜索。

日期采用该条原文披露的报道日期，不再计算跨来源事件最早日期。缺失时不以收录、刷新或上市时间替代。详情只展示标题、来源、可得日期、分类、图片与原文入口，不提炼成分、功效、研究阶段或上市信息。

关闭详情保持筛选与滚动位置；原文入口打开该资讯的来源页面，本站不提供全文阅读。

### 5. 外链展示图片，不建设图片存储服务

只保留图片地址与出处，由浏览器直接从允许使用的来源加载；不下载、转存、内嵌、代理或建立本平台图片库。

图片不可用时显示状态，不以无关图片替代，也不妨碍文字、来源入口和收藏。图片展示需要网络并受来源条件影响；外链不是自动授权，不绕过防盗链。

### 6. 持久保存个人收藏并跟随元信息更新

收藏引用同一资讯条目，不保存正文或历史快照。相同原文链接的标题与元信息可靠更新时，收藏仍指向原条目；不同链接不共享收藏。

再次打开应用后收藏保留，列表、详情与收藏入口状态一致。原文不可用时保留最后可用标题、链接和元信息；取消不删除资讯，保存失败保持上次成功状态。

## Capabilities

### New Capabilities

- `personal-intelligence-workspace`：登录后集中浏览七类标题，并在手机或桌面完成个人阅读导航。
- `fixed-source-updates`：定时或手动从核验通过的固定来源取得标题和必要元信息，明确反馈更新结果。
- `url-deduplicated-headlines`：相同原文链接只收录一条，不依赖标题语义合并跨媒体事件。
- `rule-based-discovery`：依据栏目和明确标题规则分类，提供标题搜索及组合筛选，允许未分类和未披露。
- `linked-source-images`：直接显示来源图片链接，失败时降级为文字，不建设图片存储服务。
- `persistent-personal-bookmarks`：保存个人对资讯的引用，跟随标题与元信息更新，原文失效后保留回看线索。

### Modified Capabilities

不适用。仓库尚无正式业务实现；本次修改的是待建设需求，不宣称旧原型提供真实来源、调度、登录或服务器持久保存能力。

## Out of Scope

- 文章正文采集、保存或站内全文展示。
- 外部模型、本地模型、中文摘要、自动翻译及内容分析服务。
- 跨媒体事件匹配与归并、自动提炼成分、功效、研究阶段或上市信息。
- 功效判断、合规结论、影响评分、趋势统计大屏。
- 团队协作、多人空间、会员收费、赞助和对外数据销售。
- 来源编辑后台、人工审核、导出、竞品对比、消息推送和自动报告。
- 图片下载、代理、转存或以本地副本绕过外链失败。
- 在这次文档修订中修改原型、生产代码、项目索引或设置，或提前编写技术设计和任务计划。

## Impact

### 建设与修订边界

- **阅读界面**：从摘要卡收缩为标题与必要元信息卡；详情不再展示摘要、成分、证据阶段或上市时间提炼结果。
- **后台处理**：保留来源读取、去重、规则分类、调度和持久保存，移除正文、模型和事件归并流程，不需要模型密钥或调用费用。
- **数据含义**：条目由原文链接识别，收藏引用该条目；取消原跨媒体事件和多来源归并关系。未知分类、地区、品类和日期必须可表达。
- **外部依赖**：仍需核验固定来源及图片使用条件。无模型不意味着可绕过内容或图片授权。
- **修订产物**：原位修改 [PRD](<prd.md>) 与本提案，保持各自单文件形式，不转换、不删除文件。本轮不修改 [旧原型](<prototype.html>)，其旧内容区块只作历史演示。
- **已确认设计方向**：当前会话 D-001～D-007 已确认沿用原型视觉、常开云服务器、单人密码登录、Python + FastAPI、Vue 3 + TypeScript + Vite、SQLite 和独立串行后台进程。这些选择不因范围收缩重新提问；完整实现契约仍由设计阶段负责，本提案不是技术设计批准。

### 风险与后续设计事项

1. **来源读取**：标题和图片地址是否可取得仍受栏目结构、访问限制和使用条件影响；设计需落实首批来源，不能把名单当成功接入证明。
2. **分类覆盖**：只用明确规则时会出现未分类或未披露，这是已接受边界，不以正文分析或模型静默补全。
3. **重复事件**：相同事件的不同媒体链接会分别展示，这是用户明确接受的取舍，不是漏做语义去重。
4. **日期与图片**：元信息可缺失，图片会失效；不能让缺图、未知日期阻断可读标题和收藏。
5. **旧原型差异**：视觉基准沿用，但标题版页面尚未在旧稿重新实现；旧摘要或事件演示不构成本版测试结果。
