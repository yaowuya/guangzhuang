> **历史非 canonical 资料。** 本文件形成于 FeaturePilot 计划确认前，包含实施前状态、旧分类编码和普通开发建议；不得用于驱动执行、判断完成度或替代验收。当前唯一权威计划是 `fp-docs/changes/beauty-intelligence-mvp/tasks/`，完成证据以 task owner checkbox、Git 提交和 `.fp-execute/progress.md` 为准。
>
> 原始状态：待用户确认；当时尚无正式前后端工程。本文件保留为调研过程资料，不随当前实现自动刷新。

## 目标与约束

本版为个人提供“浏览标题 → 筛选 → 查看出处 → 打开原文 → 收藏回看”的真实业务闭环。每天北京时间 07:30 更新固定来源，也支持手动刷新与重试。

已确认的产品和技术基线见[标题版需求](<../fp-docs/changes/beauty-intelligence-mvp/prd.md>)、[后端设计](<../fp-docs/changes/beauty-intelligence-mvp/design/backend.md>)和[前端设计](<../fp-docs/changes/beauty-intelligence-mvp/design/frontend.md>)。用户已明确选择普通开发流程，**现有原型是视觉基准，无需 Figma**；但不能把本计划或原型检查说成 FeaturePilot 的 Figma 视觉交付门禁已通过。

### 本期必须保留

- 单人密码登录，不开放注册；Vue 3 + TypeScript + Vite、FastAPI、SQLAlchemy／Alembic、SQLite、单后台进程、Caddy、Linux 与 Docker Compose。
- 只获取原文标题、来源、原文链接、可得报道日期及允许使用的图片外链／归属信息。页面中文，标题保持来源语言。
- 保留七类入口；依据来源栏目与明确标题规则分类。无法判断的条目进入“全部／未分类”，地区和品类未知不推断。PR TIMES 全站 RSS 是多行业流，因此“全部”可能包含非美妆标题。
- 原文链接只去首尾空格和 `#` 定位标记后比较；保留全部查询参数，不把不同媒体的同一事件合并。
- 图片由浏览器直接加载允许的第三方链接，平台不下载、转存、内嵌或代理；图片失败不阻断标题、原文和收藏。
- 五个目标来源：PR TIMES（RSS 与 Beauty 列表）、HAPPI、青眼、Premium Beauty News、COSIN Korea。各入口逐一核验访问和使用条件；未通过的不启用。**至少一个来源须通过核验并在目标云环境真实更新，才算正式交付完成。**
- 收藏持久化并引用资讯；同链接的标题或元信息更新后保持收藏，取消收藏不删除条目。

### 本期不做

文章正文采集与存储、模型调用、摘要和自动翻译、跨媒体事件归并、成分／功效／研究阶段提炼、会员和团队、来源编辑或审核后台、导出、推送、图片转存。RSS 响应可能自带正文片段：解析时只读取必要元信息，不额外请求文章详情，也不提取、持久化或记录正文。

## 设计核对中发现的边界

以下处理作为本计划的一部分提交用户确认，不改变已确认的产品目标；原设计中的相应文字存在歧义，不应由前后端各自猜测。

1. **首次登录的 CSRF 例外。** 登录前没有会话或会话绑定的 CSRF 标记。`POST /api/auth/login` 不要求已有会话标记，但必须检查同源 `Origin`、限制请求格式并限流；登录成功签发安全 Cookie 和会话标记。其余业务写请求仍同时要求有效会话、同源和 CSRF。原设计的冲突见[后端接口与认证](<../fp-docs/changes/beauty-intelligence-mvp/design/backend.md#接口权限与兼容边界>)。
2. **完全错过 07:30 的补跑集合。** 当天没有任何定时任务记录时，所有当时已核验且启用的入口都属于未完成候选；已有定时记录时，只选择仍失败或中断、且之后未被手动重试成功的入口。当日自动补跑最多一次，不追补前几天；成功内容保留。若手动任务占用定时点，结束后再按同一规则判断。补跑失败后可手动重试。

   进程重启时，先在数据库事务中将旧的 `running` 任务及其未完成入口标为中断并记录结束时间，保留已成功结果，释放活动任务唯一约束；独立排队中的 `pending` 任务不误判为中断。之后再按当天补跑规则创建任务，或允许手动重试；并发请求仍返回已有活动任务，不能让旧任务永久占用“更新中”。
3. **收藏排序。** 用户已明确确认：收藏列表默认按收藏时间从新到旧；资讯首页按报道日期从新到旧，未知日期排后。相同排序值以条目 ID 稳定排序。
4. **分页并发边界。** 维持已确认的页码分页；在数据不变时顺序确定。后台更新恰逢翻页时，新条目插入可能使跨页结果发生位移；本版不假称快照级“不重不漏”。如需严格跨更新不重不漏，应先调整接口／数据设计并重新确认。
5. **跨端字段和错误契约先冻结。** 在并行实现页面前，按下节统一 JSON、类别编码、空值、分页、CSRF 请求头和错误状态。标题列表、详情和收藏列表的每条均返回 `bookmarked`；收藏写操作返回同一语义的确认状态，避免跨页或多视图各自猜测。
6. **前端路由的部署回退。** 唯一根 Dockerfile 把 dist 复制进 FastAPI runtime；FastAPI 先保留 `/api` JSON 路由，再仅将非 API 的 GET/HEAD 404 回退到 `index.html`。Caddy 只做代理/TLS。不存在的 API、asset 和显式文件仍返回真实错误，不被页面回退吞掉。
7. **入口级来源核验。** 同一站点可有多个入口，且许可状态可能不同。为现有 `source_entries` 增加入口级核验状态、原因和依据引用；站点级状态只做汇总。没有入口级核验依据的入口默认禁用，`last_error` 不代替使用许可判断。这是已确认七表模型的字段补充，不新增表或来源管理页面。

## 跨端接口约定

全部业务接口同域 `/api`；除登录外均需有效会话。写请求携带会话绑定的 `X-CSRF-Token` 并校验同源。登录及会话查询返回有效期与 CSRF 标记，令牌存于 `HttpOnly`、`Secure`、`SameSite` Cookie，不把密码和 Cookie 写入日志或前端本地存储。

| 接口组 | 主要约定 | 关键验收 |
| --- | --- | --- |
| 认证 | `POST /api/auth/login`，`GET /api/auth/session`，`POST /api/auth/logout` | 首次登录可用；24 小时到期；退出立即撤销；未登录受保护请求 401 |
| 资讯／筛选 | `GET /api/articles`、`GET /api/articles/{id}`、`GET /api/filters` | 列表返回 `items`、`total`、`page`、`page_size`；详情与列表字段语义一致；不返回正文／摘要 |
| 收藏 | `GET /api/bookmarks`、`PUT/DELETE /api/bookmarks/{article_id}` | 一条资讯一条收藏；写操作幂等；失败保持先前状态 |
| 来源／任务 | `GET /api/sources`、`POST /api/update-jobs`、`GET /api/update-jobs/current`、`GET /api/update-jobs/{id}`、`POST /api/update-jobs/{id}/retry` | 来源仅只读；当前任务可在刷新后恢复；无可启用来源时明确提示，不伪称成功 |

条目对象统一包含 `id`、`title`、`source`（`id`、`key`、`name`）、`original_url`、`reported_date`、`category_codes`、`region`、`product_type`、`image_url`、`image_credit` 和布尔值 `bookmarked`。列表、详情和收藏列表均使用同一语义；收藏写操作成功后返回 `article_id` 与 `bookmarked`。未知日期、地区、品类和图片使用 `null`；未分类使用空数组。

七类稳定编码以 canonical 接口账本为准：`new_products`（新品发布）、`trends`（趋势洞察）、`new_ingredients`（新原料）、`research_technology`（研发技术）、`packaging_formulation`（包装与剂型）、`oem_odm` 和 `regulation_compliance`（法规与合规）；类别名称和编码分开保存，未分类不是第八类。中、英、日、韩语样例规则只依据来源栏目与标题，不能冒充完整市场覆盖。

列表默认 `page=1`、`page_size=20`，上限 100；日期区间含两端，未知日期不命中有日期边界的筛选。错误响应统一包含 `code`、`message` 和 `request_id`：无效筛选 400、未登录 401、Origin／CSRF 校验失败 403、不存在的条目或任务 404。无已启用来源或无可重试入口返回可识别的 409 状态；提交新任务返回任务 ID，已有活动任务返回同一 ID；无当前或历史任务时返回 `job: null`。

来源状态响应按站点列出入口，每个入口分别返回核验状态、可说明原因、是否启用、最后成功时间与最近错误；许可依据与访问故障分开记录。任务状态使用 `pending`、`running`、`succeeded`、`partial`、`failed`、`interrupted`。实现时先用同一份契约测试固定这些语义，再并行开发前后端；无匹配条目保持未分类，不能读取正文或调用模型补全。

## 阶段与任务

除工程初始化外，每个任务按“先写可观察行为的失败测试 → 最小实现 → 通过测试并自审”进行。下面的任务顺序是依赖建议，不等于自动并行实施授权；前后端涉及同一接口时先完成接口约定与消费者测试。

### 阶段一：工程基座与契约

**1. 建立最小工程和测试入口。**

- 后端建立 Python 项目、FastAPI 应用和 pytest 测试配置；前端建立 Vue 3、TypeScript、Vite、Vue Router 与前端测试配置。
- 新建必要目录、依赖声明和锁定文件；不创建 Redis、模型 SDK、图片代理或大型 UI 组件库。仅提供无真实密钥的配置示例。
- 测试空应用可启动、路由可挂载，初始数据库可创建；记录安装与运行命令。初始化测试不能当作业务验收。

**2. 固定跨端契约与测试数据结构。**

- 落实上述字段、错误码、分类稳定编码、分页默认与上限、登录前／后 CSRF 规则及任务状态；前后端引用同一份接口文档和契约测试。
- 先验证非法参数 400、未登录 401、无权限 403、无记录 404、字段空值和收藏标记的一致性。测试数据只能用于单元／集成验证，不能冒称真实来源。

### 阶段二：后端基础能力

**3. 七类持久数据和迁移。**

- 使用 SQLAlchemy 和 Alembic 创建来源、来源入口、资讯、收藏、更新任务、入口结果和服务端会话七张表。
- 在临时 SQLite 中先测外键、链接唯一、收藏唯一、每任务入口唯一、同一活动任务唯一以及每日定时／补跑唯一；终态必须释放活动约束。空日期／未知属性不伪造。
- 保持事务短小；同机数据库使用持久卷，不保存正文或图片字节。

**4. 单人登录与请求保护。**

- 验证 Argon2id 密码摘要、服务端随机会话、24 小时有效期、退出立即撤销；多标签会话使用一致的会话绑定标记。
- 先测首次登录无需既有会话 CSRF、但必须同源及限流；其他写请求缺会话、错误 Origin 或 CSRF 必须失败。日志不包含密码、Cookie 或密钥。
- 页面路由守卫仅改善体验，不能替代后端鉴权。

**5. 标题、链接去重、分类和查询。**

- 先测同一链接的空格和 `#` 差异归并；不同查询参数、参数顺序和不同媒体链接分别保留；不丢失已有可靠元信息和收藏。
- 标题、分类、地区、品类和日期组合筛选与服务端分页；未知值如实保留。首页和收藏分别使用已确认排序。
- 对源链接和原文／图片 URL 校验安全协议与可信目标；普通文本安全转义，不能把 HTML 转义当作 URL 安全校验。

**6. 服务端收藏与错误处理。**

- 先测重复收藏／取消、跨列表／详情状态一致、数据库失败不假报成功、取消不删除条目。
- 用实际 SQLite 重启服务，验证收藏及同链接元信息更新后仍然存在。

### 阶段三：来源、任务和恢复

**7. 来源核验与受限读取。**

- 按五站固定清单记录每个入口的核验状态、原因和使用条件证据，并通过只读接口分别返回；同站不同入口允许状态不同。未确认条件的入口默认禁用；Premium Beauty News 及其他受限来源不能默认采集。
- 只访问允许的固定入口；验证超时、响应体积、请求次数、跳转和 DNS／连接目标检查，阻断本机、私网、云元数据地址和重定向绕过。保持正确目标主机与 TLS 校验。
- 对允许使用的 RSS 或公开列表解析标题及必要元信息；测试含正文哨兵、脚本、缺失标题／链接、无许可图片、零条和截断数据。不得执行页面脚本或访问文章详情。

**8. 持久任务、单后台进程与恢复。**

- 先测并发刷新只产生一个活动任务；手动刷新处理所有已启用入口，重试仅处理失败／中断入口。
- 用受控时钟覆盖 07:30 正常执行、完全错过、被手动任务占用、部分成功后中断、重试成功及多次重启。验证中断旧任务先进入终态并释放活动唯一约束，当前任务接口不永久显示运行中；再按上文规则当天自动补跑最多一次，不回放多日。
- 逐入口提交成功结果；区分成功、部分成功、失败和无新增，不清空旧内容，不冒充最后成功时间。

**9. SQLite 一致备份与恢复。**

- 每日使用 SQLite 一致性备份，保留最近七份成功备份；测试并发写入、WAL、磁盘错误和中断。失败的备份不能覆盖或删除已有健康备份。
- 在独立数据库做完整性与外键检查。正式恢复时先停止 API／后台写入，保全现有数据库及 WAL／SHM；明确可能丢失的时间窗口，经用户确认后恢复，再启动并校验。
- 本机七份备份不覆盖整机或磁盘损坏；异地备份不在本期自动增加。

### 阶段四：前端与联调

**10. 同源请求、登录和工作台外壳。**

- Vue 小型组件复用原型的配色、排版、导航与间距；新增登录页、七类导航、全部、收藏和来源状态入口。
- 测试登录失败、会话过期、安全的站内返回、写请求 CSRF 和不自动重放写操作。来源状态只读，不提供启停或编辑按钮。
- 未登录不能通过页面或直接请求读取业务数据。移动导航隐藏时不进入键盘焦点顺序。

**11. 标题列表、筛选和出处侧栏。**

- 标题卡只显示标题、出处、可得日期、分类及允许的图片；删除旧原型摘要、成分和研究阶段内容。
- 关键词、分类、地区、品类、日期和页码同步 URL；条件变更返回第一页。打开详情、关闭或浏览器返回后保留条件、焦点与阅读位置。
- 测试七类、未分类、条件交集、未知日期、无结果、清除条件和真实原文链接。外部链接仅在用户主动操作时打开。

**12. 图片、收藏和更新状态联调。**

- 图片直接向允许的来源请求；无图、失败、拒绝外链和离线只降级图片区域。不得用无关照片替代，不能使用站内代理。
- 用真实后端实现收藏、取消、保存失败状态；首页、详情和收藏视图结果一致。更新面板分别显示进行中、无新增、部分失败、全部失败与受限来源。
- 组件测试可使用受控网络响应制造异常；该结果不能作为真实浏览器端到端通过的替代品。

### 阶段五：验证、部署与交付

**13. 实际浏览器与前后端联验。**

- 本机已验证 Playwright CLI `0.1.22` 和 Chrome 可启动；实现后使用真实前端、FastAPI、后台进程、隔离 SQLite 与测试账户。
- 通过页面完成登录 → 查看标题 → 筛选 → 打开／关闭详情 → 收藏 → 重启服务并回看 → 取消收藏；验证实际网络请求、服务器鉴权和数据库持久化。测试数据使用已获准来源的真实标题，测试收藏通过页面清理。
- 核查图片请求直接指向来源，并验证图片失败时文字、出处和收藏可用；人工模拟网络故障时明确记录模拟范围，不把源站授权或稳定性说成已证明。
- 使用 1440×900、768×1024、390×844 视口检查；针对实际断点 1100 px、640 px 两侧补测。比对原型的布局、色彩与层级，不要求含旧摘要的全图像素一致。
- 覆盖键盘、焦点恢复、无横向溢出及减少动态。若没有真实手机或可操作软键盘的模拟器，软键盘遮挡情况明确标为未验证。

**14. 云部署与真实来源验收。**

- 按已确认方案建立 Compose 服务、Caddy HTTPS、数据库与备份持久目录，确保只运行一个后台进程。
